## Launchpad：从要求到交付

Launchpad 是为 2026-09-28 展示准备的本地发布清单项目。人物、事项和初始验收状态均为虚构；页面保留编号、负责人、优先级和未完成项，串起读取要求、浏览器操作、CSV 导出与任务证据。

演示使用隔离的 DSH 环境和本地受控的「演示模型」。作者安排模型响应与工具调用步骤，原生工具循环实际执行文件读取、检查命令、浏览器连接和证据运行。它展示 OMD 的工作流程，不评估供应商模型的自主规划、准确率或速度，也不声称现场从零生成了这个预先准备的页面。

同一案例中的关键要求始终保持一致：

- 搜索、分类、状态筛选和勾选结果在刷新后恢复。
- 中文 CSV 使用 UTF-8 并带 BOM，固定六列：编号、事项、负责人、优先级、状态、验收说明。
- 保留未验收事项；“已验收”表示清单中的勾选状态。

实际流程先用原生 `read` 读取需求，再用 `bash` 运行关键逻辑测试，并通过 `computer_use` 打开真实网页。演示作者实际操作筛选、勾选、刷新和下载，期间手动接管再恢复助手控制。随后把检查挂到 `todo_write` 的任务上，由 `verify_link` 实际运行；挂接记录与 PASS 回执分别呈现。

### 检查与下载分别证明什么

| 证据 | 实际核对的内容 |
| --- | --- |
| 关键逻辑单测 | `core.test.mjs` 的 3 项检查通过：组合筛选保留原编号、恢复有效筛选与勾选状态、CSV 的 BOM／六列／逗号引号换行转义。 |
| 浏览器操作 | 在实际网页中筛选、勾选并刷新，检查状态恢复；再点击导出取得文件。单测不代替这些页面操作。 |
| 筛选后的真实下载 | 读取下载文件，确认 UTF-8 BOM、六列标题和 1 条预期匹配事项。 |
| 完整清单的真实下载 | `verify-download.mjs` 独立解析实际下载文件，确认 BOM、6 列、8 条事项，其中 3 条待验收；所有字段与源数据逐项一致，原生证据运行返回 PASS。 |

页面初始的勾选、百分比和“已验收”是示例业务数据，**不是 OMD 功能的验收结果**。本次通过的项目逻辑检查与实际下载核验，有各自的运行记录。
