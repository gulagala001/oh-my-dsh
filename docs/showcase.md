## Launchpad：从要求到交付

这组实拍于 2026-10-10 在隔离的 DSH 0.2.1-alpha.2／OMD 0.13.0 开发候选中重新拍摄，内置 OpenCU 1.5.0。人物、清单和状态都是虚构资料；页面事先准备，不声称由模型现场生成。

本地受控模型安排响应和工具调用，DSH 原生工具循环实际执行。它展示产品的操作与交付流程，不评估供应商模型的自主规划、语义摘要质量或速度。没有使用真实订阅账号、私人材料或桌面权限。

要求始终一致：CSV 使用 UTF-8 + BOM，固定六列“编号、事项、负责人、优先级、状态、验收说明”；保留八条事项和三条待验收项，实际下载并逐字段核对，再交付 CSV 与要求文件。

| 实际步骤 | 证据范围 |
| --- | --- |
| 读取要求与建立任务 | 原生 read 读取要求；todo_write 摘录用户原话，建立两个有来源锚点的任务。 |
| 网页与下载 | computer_use 打开本地网页，点击导出并保存真实下载；浏览器检查另外实际验证搜索、状态筛选与刷新后的恢复。 |
| 文件核验 | 独立脚本读取下载文件，检查 BOM、六列、八条事项、三条待验收项及全部字段与源数据一致。verify_link 运行脚本，保存实际 PASS 输出。 |
| 交付 | 原生 present 交付 CSV 和 Markdown 要求文件，工作台展示完成状态与核验记录。 |
| 压缩与回查 | 实际预处理，再执行仅摘要与全量压缩；原始记录保留。recall 搜索原话，返回最初的 CSV 要求，供继续核对。 |

清单中的五条“已验收”和三条“待验收”是**示例业务数据**，不表示 OMD 的工程验收数量。两个工作台任务和脚本输出是这次演示的实际执行结果。Windows 实测、真实桌面权限和公开发布在示例清单中保留为待验收。
