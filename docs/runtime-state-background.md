# 运行状态与后台选项

[文档目录](README.md) · [使用指南](usage.md) · [Ultra 与 Workflow](workflow.md)

这页讲 AI 能看到的运行状态、会话预算和后台任务，帮你分清"正在跑""在等结果"和"真的做完了"。

这些选项在 **设置 → Oh My DSH → 智能体**：**CoT 前置** 和 **后台优化** 默认开，**CFR**、**运行状态** 和 **预算提示** 默认关。保存后从下一次模型请求开始生效，已有会话也一样。

## 运行状态

开启后，AI 在这些时候收到一份最新状态：你发新消息、任务清单更新、压缩后刷新，或者状态块丢失时。同一步只发一次。后台任务、时间或 Token 变化本身不会触发。

状态包括：采样时间、当前轮次和步数、本轮已用时间、当前上下文的 Token 估算、最近确认的模型窗口和已注册的后台任务。第一次请求显示 `turn 1 · step 1`。这些是采样时的数字，不会每步自动刷新；窗口大小也不是剩余额度。不会编造进度百分比、截止时间或预算。

AI 可以随时用 `runtime_status({})` 查最新状态。关掉运行状态后，任务、原文和验证证据都还在。

## 会话预算

**向模型提供预算** 默认关，可以单独开。没设的项显示"无限制"。

在对话里发 `/预算 token=100k 轮次=30 时间=20m`，三项可以任选或组合，`/budget` 也行，命令菜单能补全。这个命令由 DSH 处理，不调用模型。Token 支持 k／m，时间支持 s／m／h 或秒／分钟／小时。

| 命令 | 作用 |
| --- | --- |
| `/预算` 或 `/预算 查看` | 看当前用量和上限 |
| `/预算 token=200k` | 改一项上限，其他不变 |
| `/预算 时间=无限制` | 清掉一项上限 |
| `/预算 无限制` | 清掉全部上限 |
| `/预算 重置` | 上限不变，重新计数 |
| `/预算 关闭` | 关掉本会话的预算，再设置时从头算 |

- **Token**：本会话、后台和子智能体调用的输入、缓存输入和输出之和，推理 Token 不重复算，没有用量的调用单独标出。
- **轮次**：只算本会话主执行的模型调用（包括失败的），后台和子智能体不算。
- **时间**：模型和工具运行的时间，不算等你回答、空闲和重启停机的时间。
- 预算按会话保存。分出的分支单独计算；Workflow 的子智能体用量算在发起它的会话里。
- 超过 100% 也不会强制停止，也不会触发收尾提醒。

**每轮注入预算** 默认关。开启后可以选每轮、每 3／5／10 轮或自定义间隔，到了间隔只追加预算，不重发其他状态。

Workflow 的 [`+500k` 输出目标](workflow.md#输出-token-目标) 是另一套机制，和 `/预算` 互不影响。

## 后台任务

开启后台优化后，OMD 主会话里的命令行调用会这样处理（子智能体、原生预设和第三方工具保持各自的规则）：

| 调用方式 | 行为 |
| --- | --- |
| 直接调用 Shell，不写 `run_in_background` | 先等 10 秒（`yieldMs` 可设 250–30000 毫秒），还没完成就返回任务编号，原超时继续计时 |
| `run_in_background: false` | 一直等到结果 |
| `run_in_background: true` | 立刻返回任务编号，可以读增量输出；不设命令超时，要用 `job_kill` 停 |
| 在 `run_code` 里不写后台参数 | `await` 一直等到最终结果 |

- 转到后台不会重新执行命令。自动转后台的任务结束后给出捕获的输出；想在运行中看日志，请直接用后台方式启动。
- 停止或卸载时会取消并等待自己启动的进程，重启后不会重跑旧任务。
- 完成通知带任务编号、结束状态和一段输出预览，输出不完整时继续用 `job_output` 读。完成只表示跑完了，退出码、超时、截断和结果还要自己看。
- 顶层直接调用 `job_output({job_id, wait:true})` 且不写 `timeout_ms` 时，会一直等到有事发生：返回的 `wakeReason` 是 `completed`（完成）、`user_input`（你插话）、`other_completion`（别的任务完成）或 `timeout`（超时）。被唤醒不代表目标任务完成，也不会取消它。
- 等待期间输入框的发送按钮显示"现在发送"，按 Enter 直接插话。

## OMD-PTC

开启后台优化后，在 OMD-PTC 会话里 `job_output`、`job_list`、`job_kill`、`runtime_status` 可以直接调用，其他工具仍通过 `run_code`，权限和取消不变。相对路径跟随当前执行目录。

```js
return await tools.bash({
  command: "pnpm test",
  description: "Run project tests",
  run_in_background: true
});
```

它会先返回任务编号，AI 可以先做别的再等结果。Windows 用 `tools.pwsh`。`run_code` 内部的等待仍受整段程序的超时限制。

## Todo 阻塞处理

没有能执行的下一步时，AI 可以调用：

```json
{"op":"pause_turn","reason":"缺少服务连接；需要先启动服务才能继续验证。"}
```

这会停掉本轮的待办催促，让 AI 正常说明卡在哪。未完成的任务、证据和 BT 设置都不变，你发新消息或下一轮会恢复检查。同样的收尾提醒在一轮里只发一次。它不会停止后台进程，也不会暂停 Goal；要停进程仍用 `job_kill`。

## 其他

- 这些功能对应 DSH 0.2.2-rc.2，具体组件见 `package.json` 和 `vendor/dsh.json`。DSH 原有的工具注册、调度、后台任务、Shell 和输入框行为都保留。卸载时只撤回 OMD 自己加的部分。
- 在插件页启用或停用整个 OMD 时，页面会自动刷新，会话历史、设置和文字草稿保留，附件要重新添加。只改这些选项不会刷新页面。
- 运行状态和预算会占一点上下文。压缩时只保留最新的一份。不会因此多调用模型。
