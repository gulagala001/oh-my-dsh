# 装好后的第一次使用

[English](getting-started_EN.md) · [文档目录](README.md) · [安装教程](upgrade.md) · [使用指南](usage.md) · [排障](troubleshooting.md)

装好并完整重启后，先完成一个小任务，确认模型、文件工具和交付能连起来。还没安装时，选择[桌面版](upgrade.md#desktop)或 [Web 版](usage.md#安装到现有-dsh推荐)。

## 1. 确认版本与模型

打开左上角品牌旁的版本图标，查看 **当前版本**：

| DSH | 公开 OMD 当前版本 |
| --- | --- |
| `0.2.1-alpha.1` | `0.2.1-alpha.1.omd.0.10.0` |
| `0.2.0-rc.2` | `0.2.0-rc.2.omd.0.10.0` |

“最新版本”只是远端发布信息。版本没变、入口缺失时，先[核对运行环境](troubleshooting.md#先确认是否装到了正在使用的环境)。

OMD 使用 DSH 已有的模型和凭据，不附带账号。选择支持原生工具调用的模型；理解截图还需图像输入。先做文件任务，无需同时准备桌面权限或 Chrome 扩展。

## 2. 选择会话、目录和范围

新建会话，选择 **Oh My DSH** 预设和一个含 README 的目录。已有会话保留原预设，安装不会切换所有旧会话。

首次发送前选 **会话隔离** 或 **项目共享**：独立任务用隔离，同项目后续会话需要共享资料时用项目共享。开始后锁定，换范围需新建会话。开发分支还提供全局范围，见[上下文与记忆](usage.md#上下文与记忆)。

**安装默认允许完整文件／命令访问，并关闭执行审批；profile 的显式覆盖优先。** 发送前确认目录和实际权限符合本次任务。

<details>
<summary>没有项目，也可以开始</summary>

取消已选工作区后直接聊天。首次发送才会在 DSH 所在电脑创建独立目录，默认位于文稿（Documents）/DSH/日期/首条消息名。继续聊天用原目录，另开聊天建新目录。[无项目聊天](usage.md#无项目聊天)。

</details>

## 3. 让助手读文件并交付结果

可发送：

> 读取当前目录的 README，说明项目用途、启动方法和运行条件。把你实际找到的信息整理成 project-start.md，并列出 README 没有说明的事项。完成后打开这个文件供我查看。

观察是否读了正确文件、工具是否成功，再打开交付文件核对来源。README 没写启动方法时应保留“未说明”，不猜命令。没有 README 时，换成准备好的非敏感文件。

结果应是一段有依据的说明和一个可打开的 Markdown 文件。这确认本次模型与文件流程，其他组件按需准备。

## 4. 多步骤任务：要求、操作、检查一起看

打开 **工作台 → 任务与验证**，让助手摘录要求、记录待办并实际检查产物：

> 按我提供的清单导出 CSV。保留未验收项，检查编码、列顺序和全部字段，完成后交付文件和检查结果。

实拍中的虚构发布清单保留 8 条事项、3 条待验收，使用 UTF-8 + BOM 和固定六列；实际下载文件的检查通过。

[![任务页面：原始要求、两个工作任务与实际 PASS 输出](site/media/launchpad-tasks.jpg)](showcase.md)

*业务“已验收”是示例数据；文件检查是实际结果。[完整案例](showcase.md)。*

## 5. 认识常用入口

| 入口 | 什么时候用 |
| --- | --- |
| 输入框星星 | 优化未发送草稿，支持原稿和版本恢复；每次优化额外调用模型。 |
| **任务与验证** | 查要求、状态和证据；BT 待办提醒默认开，验证提醒默认关。 |
| **上下文** | 查摘要、资料和来源；刚开始为空属于正常情况。 |
| **记忆 · Dream** | 开发分支的短记忆入口，自动整理默认关。 |
| **监控** | 查调用、用量和上下文；后台调用也有费用。 |
| **电脑** | 查看网页或应用画面；手动操作前停止／接管，完成后恢复。 |
| **设置 → 外观** | 切换主题、配色、字体和背景。 |
| **基础组件** | 按需准备 CodeGraph、浏览器与桌面控制。 |

停止会话、停止电脑操控和关闭预览是不同操作。接下来读[电脑操作](usage.md#开始使用)，遇到问题从[症状表](troubleshooting.md#按症状处理)开始。
