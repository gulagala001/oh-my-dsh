# DeepSeek Workbench

DeepSeek Workbench（`dsh-deepseek-workbench`）把 DeepSeek 网页聊天和开放平台接入 DSH。当前源码版本为 `0.1.0`，尚未独立发布；OMD 随包内置并默认启用。现有公开 OMD 安装包不能据此视为已包含此功能。

## 入口与使用

- **网页聊天**：左侧“新会话”下方的 DeepSeek 网页聊天入口，打开主内容区的原生风格消息区和输入框。聊天不占用右侧栏。
- **开放平台**：设置中的账号页，用于打开 DeepSeek 开放平台。
- **推荐插件**：卡片提供“打开网页聊天”和“打开账号页 / 开放平台”。卡片实时读取已挂载服务的启用状态；未启用时显示原因并禁用入口。
- **导入后继续**：在 DeepSeek 网页打开需要继续的会话，使用工作台导入入口，将可提取的历史创建为真实 DSH 原生会话。打开导入结果后，由用户写下一条消息继续；接续使用所选的 DSH 模型与 preset，原网页会话保留。

API 开放平台优先使用 DSH 原有的账号视图，直接复用 DSH 登录的 DeepSeek 账号。网页聊天的现有官方协议没有从 DSH 平台授权交换登录的接口，仍需单独登录一次，之后持久复用。主界面以 DSH 风格呈现聊天；官网只承担后台传输与登录验证。

点击“在 DSH 中继续”直接读取历史、迁移并打开原生会话。成功取得的附件写入 DSH 原生附件存储；其他附件保留名称和链接。未加载的历史、无法识别的内容和附件读取失败会显示迁移说明。导入不会把整段历史粘贴为新提示词，也不会自动发送下一条消息。

## 桌面与 Web 的边界

桌面内嵌网页依赖宿主提供的原生 guest / WebContents 浏览器桥接。持久登录需要宿主提供稳定的会话分区；下载需要宿主提供下载事件与文件保存桥接。当前为这些能力准备了宿主适配源码，原版宿主尚有桥接限制，不能据此宣称已实现持久登录和下载。插件入口已启用不代表原生网页能力已经可用。

Web 宿主没有桌面原生 guest 能力时，网站也可能阻止 iframe 嵌入。此时无法使用原生网页聊天桥接，需要在外部浏览器访问官网。外部浏览器不能自动获得 DSH 内部网页桥接，导入流程应按页面的降级提示操作。

可用能力取决于当前宿主提供的桥接；缺少能力时按页面提示打开外部浏览器。

## 更新与排障

内置工作台随 OMD 更新，推荐插件的自动更新不会查询 npm 或下载独立工作台安装包。推荐页也不提供工作台的安装、更新和卸载操作；这不影响其他第三方推荐插件的管理。

显示“已内置·未启用”时，检查宿主插件配置与 OMD 是否正确加载。工作台已启用而网页不可用时，先查看工作台显示的宿主能力和错误提示，或在外部浏览器访问官网。

独立插件源码位于 [`plugins/deepseek-workbench`](../plugins/deepseek-workbench)。当前没有已发布的独立 npm 包或专用 GitHub 发行入口。

## 共装与数据保留

后端在同一个 Cordis Host / `deepseekWorkbench` 隔离域只注册一份服务，两份插件分别持有 owner lease。服务不再成为第一份插件的子 fiber，因此两加载顺序中卸载先加载者，另一份仍保留相同 importer、已挂载 API 与去重状态；最后 owner 卸载撤回 API，不删除导入记录、原生会话或附件。前端仍以 window ownership 去重，leader 卸载释放自己 guest 并转交入口。

附件没有签名来源、只有本地 blob 且无法读取、或链接不能安全进入迁移请求时，保留名称并提示，不静默丢弃附件专属消息。结构化正文同时含思考、工具或未知角色时仍报告省略。原生重试按钮重新读取迁移服务状态，失败恢复后不永久禁用导入，也不自动重放导入。

独立打包需要匹配的源码、SDK、组件和锁文件，不能只修改 peer 版本。桌面桥接配置见 [`desktop/README.md`](../plugins/deepseek-workbench/desktop/README.md)。
