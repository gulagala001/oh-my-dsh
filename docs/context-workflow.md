# 上下文整理与原文回查

[文档目录](README.md) · [首次使用](getting-started.md) · [设置说明](usage.md#settings)

本页说明当前源码的上下文整理、自动压缩与原文回查。版本和安装条件见[安装指南](install.md)，旧固定发行仍以对应 tag 文档为准。

## OMD 与 Billion Context

右侧 OMD 控制台 → **上下文 → 上下文管理** 可按会话选择 OMD 或 Billion Context（BC），默认 OMD。当前适配 DSH **0.2.1-rc.2** 与原版 **billion-context 0.1.202**。在设置的第三方功能中安装并启用固定版本，再选择 BC；安装包来自[原作者 ranxianglei](https://github.com/ranxianglei/billion-context)，不修改 BC 包。

| 功能 | OMD 模式 | BC 模式 |
| --- | --- | --- |
| 自动压缩 | 原版／主动异步及已开启的 Auto Compact | BC 原生压缩；保留 OMD 的设置，切回后继续使用 |
| 分段档案、Dream、任务、人格、原文与附件回查 | 正常运行 | 正常运行；当前任务、运行状态与记忆作为受保护上下文提供给 BC |
| BC 搜索、恢复、规则和诊断 | 保留原生入口及已有 BC 数据 | 保留原生入口 |
| 手动压缩和资料表示切换 | 明确操作后应用 | 明确操作后应用，并同步 BC 历史边界 |
| 分支、侧问与回退 | 沿用各自范围 | 分支继承后独立保存；侧问不修改父会话；回退后重新对齐 BC |

只有自动压缩的执行者互斥；OMD 模式隐藏并拒绝 BC 的 `compress`／`absorb` 压缩写入工具。普通工具模式与 OMD-PTC 均沿用原生 BC 工具，PTC 通过 `run_code` 调用。已关闭的独立功能不会因选择 BC 被自动开启。

执行中的切换在下一次请求边界生效。切回 OMD 时，若本地原文超过模型窗口的安全范围，先利用 OMD 档案准备可发送的表示；无法完成则保留 BC，并显示原因。切换、停启和重启保留原始日志及资料。已选择 BC 而 BC 不可用时，请求明确失败，不把原文悄悄直发。BC 自身有独立更新设置；当前适配会逐次核对代理版本，升级到未适配版本时保留历史并提示。

界面区分 **BC 发送上下文估算** 与 **本地历史**，二者不等同于提供方账单。档案、Dream 等独立后台请求保留各自输入与预算，不进入主会话的 BC 压缩状态。记忆缓存模式仍复制宿主主请求前缀；BC 在发送阶段改写主请求，后台缓存命中不作保证，缓存前缀不适合预算时改用受同一预算约束的分段请求，原文仍保留。其他模型协议、平台及 BC 新版本须单独验证。

## OMD 异步压缩

右侧工作台 → **上下文 → 异步压缩** 可为当前会话选择 **原版异步** 或 **主动异步**，选择按会话保存。新会话和未保存选择的旧会话默认原版异步。

原版异步在后台预处理摘要和详细资料，再由中枢决定保留、详细替换或简要替换，继续使用既有触发频率与手动入口。主动异步使用独立后台请求，根据当前对话决定是否需要整理、整理哪些内容；两种模式中主模型都继续工作，只在后续请求应用已经准备好的结果。切换会取消本会话旧模式尚未完成的后台请求并忽略迟到结果，已保存的原文、摘要和详细资料保持可回查。

主动异步尽量复用主请求前缀，实际缓存命中取决于提供方及请求内容。后台请求仍产生用量，不保证节省费用；可在 OMD 控制台的调用日志查看提供方返回的用量与缓存统计。

主动异步优先沿用最近一次成功且可用的主请求模型、工具和历史前缀，仅在末尾追加整理任务，不使用原版预处理／中枢的独立模型配置。最新前缀放不下完整整理任务时，可使用同一路由、当前用户要求下保留的较小成功前缀，并在末尾提供所选范围内的新内容。重启或切换到该模式后，没有成功请求快照也可使用当前路由处理完整分段。新增事件达到既有间隔或上下文压力达到 70% 时检查，检查间隔沿用中枢最短间隔，新原文仍须达到最低文本量及完整工具往返要求。同一请求快照下的相同候选不反复检查；手动“检查是否整理”可明确请求一次检查。回复只生成整理结果，不执行主会话工具；无效摘要保留原文。关闭上下文或改变主请求模型参数会取消旧请求，切回原版可继续使用已校验的准备结果。

原版异步默认整窗预处理。用户消息、提醒、旧摘要和附件不会切断窗口；系统提示词及前置 CoT 原位保留，工具往返与近期保留区仍受保护。

设置 → Oh My DSH → 上下文与记忆提供全局开关 **记忆缓存模式**（`memoryCacheEnabled`，默认开启；保留已保存的开关选择）。开启后，原版异步及 Auto Compact 内部的预处理复制最近一次成功且可用的主执行请求，保留相同提供方、模型、系统提示词、工具与消息前缀，仅在末尾追加预处理提示及本次精确范围。回复只生成 JSON 摘要，继续使用原有校验、中枢决定与原文／详细资料归档。没有可用快照或缓存前缀加任务超预算时，改用同一路由的独立分段请求；缓存复用不再是整理的前置条件。关闭后沿用原后台预处理模型配置；中枢始终使用原后台模型配置，已保存的设置保留。主动异步已有相同前缀机制，决策流程不变。

主请求快照之后刚产生、且已被原分段规则选中的回复／工具结果，仅作为过滤后的增量附在末尾，避免等待一个包含自身回复的输入快照；已有主请求前缀保持不变，处理窗口及完整工具往返规则不变。

主请求增长或新请求尚未成功时，不会清除已有可用前缀或取消同一路由下正在执行的预处理。最新前缀放不下完整预处理任务时，按新到旧检查保留的成功前缀，选择能容纳本次任务的一份；前缀与追加内容仍一并受输入预算约束。确实无可用预算时，流水线说明预算不足，可提高预处理输入预算或手动压缩；不会误显示为尚未成功请求。调大预算会恢复已有可用前缀上的等待任务；首次请求过大或冷恢复缺少快照时，可直接整理分段，不需要等另一次主请求。快照仅在内存中保留，切换路由或释放会话后清除。

预处理输入预算按完整模型请求计量，包含系统提示、工具定义、消息和媒体；字符数、UTF-8 字节和传输元数据不会当作 token。输出上限单独从模型窗口预留。未提供精确分词能力时标记为估算；成功前缀的提供方实测输入可用于该前缀加新尾部的预算。

记忆缓存模式尽量复用前缀，实际命中由提供方返回，不保证每次命中或更省费。后台请求仍产生用量，可在调用日志核对提供方返回的用量与缓存统计。

基础摘要只写范围内实际操作、改动与观察到的结果，简短平铺直叙，不复述需求或前文，不写未来计划和未完成事项。用户原话由程序逐字、按顺序归档；文档、图片、附件统一为“详细资料”。详细模式一起携带，简要模式一起退出上下文并保留回查索引。中枢不再合并记录；`recall({id, asset: 1})` 可重新打开第一个原始附件。

**本版**：同一次预处理另存有原话依据的用户决定摘要，事实摘要规则保持不变。[Dream](dream-memory.md) 在后台按“会话 → 项目 → 全局”整理短记忆，不替代当前对话的压缩。已注入的记忆与回查工具结果不再作为新增事实摘要输入，避免反复整理同一历史材料。

原版异步中，用户发言不直接触发中枢，也不取消已有中枢方案。自动处理按新增摘要数量和配置间隔运行；同一预处理批次完成后统一评估。手动触发、启用后的空闲处理及有限失败重试保留。

流水线会显示已准备摘要数量及中枢触发数量；等待累计摘要与等待判断间隔分别展示。

设置提供“按消息边界分段”（默认关闭，开启恢复兼容行为）。首批自动预处理先扣除近期保留区、受保护消息、启动提示、任务状态及纯任务管理／回查调用，待当前可选窗口中的有效事件达到目标分段数（默认 48 条）后才触发；计数以当前仍然有效的原文为准，回退掉的旧事件不计入。首次成功后恢复原来的新增事件间隔（默认 48 条），无需每批重新凑满有效事件；重启或继承已有摘要不会重新算作首批。气泡、总览和上下文页会显示“本轮新增 39/48 条 · 还差 9 条”，并单列待处理总量；运行、失败和其他等待原因优先显示。两者都须达到最低文本量（默认约 8,000 tokens），一次只处理一窗；文本量再大也不能提前触发。未达到最低文本量时保留计数与原文，继续积累。只有实际预处理失败后的重试才可补齐多窗（默认最多 2 窗），每窗仍受最低文本量限制。单窗输入预算约 300,000 tokens、摘要目标 1,200 字符、后台并发最多 2 个、失败最多自动重试 2 次。积压、首批门槛和摘要输入共用材料筛选；参考前文、用户原话、旧摘要、控制消息和附件二进制不计入最低文本量。首批窗口受输入预算阻挡时明确提示预算不足，不以小批次自动绕过门槛。空闲预处理默认关闭，启用后也遵守正常触发门槛。手动重新准备可跳过事件间隔，但仍受最低文本量限制；实际失败后的手动重试同样可补齐多窗。频率默认使用适中档：48 条新事件、48 条窗口、每 3 段新摘要评估中枢，中枢最短间隔 60 秒、自动替换最短间隔 30 步；升级保留已保存的参数。

替换前后使用同口径估算，计入历史推理、文本、工具往返与路由附件成本；这不是提供方的精确 token 账单。界面分别展示当前消息数、原始事件覆盖数、资料数量、剩余积压和估算节省量。图片接近请求上限时仍批量卸载旧图，原件保留。pi-ai 路由按提供方实际图片请求表示计算 Base64 总字节，超过图片预算 90% 时批量卸载最旧表示，目标降至 60%，优先保留最近一批及至少两张图片；最新图片本身过大时仍遵守宿主硬上限。不删历史附件或图片文件，可重新读取；减少前缀变动不保证缓存或省费。空闲预处理默认关闭，启用默认等 90 秒，并仍遵守正常触发门槛。

预处理回复未通过原话、格式或长度校验时，仍拒绝该回复并保留原文。短重试用尽后，新增真实会话事件再次达到正常间隔时会自动尝试一次；再次失败则等待下一批新事件，避免永久停摆或对同一输入反复调用。成功后按既有恢复批次补齐摘要。保存的旧校验失败也按此规则恢复，界面会显示“等待新增事件后自动重试”。

校验失败会指出具体字段和原因，例如原话序号不在本批、引用与原文不匹配、单项或总长度超限；长度错误包含实际长度和上限。下一次重试会收到相同的具体诊断，不放宽原话校验，也不额外增加自动重试次数。

后台沿用主会话模型时，已成功的同一路由主请求可为此前可恢复的提供方失败触发一次恢复尝试，包括服务恢复或账户余额恢复后的情况。退避期间收到的恢复信号会保留，重启后按原截止时间继续，发送前重新核对当前设置。独立后台模型不会因无关的主请求成功而重试；不支持的请求参数等配置错误仍保持明确报错。已有退避、校验、最低文本量、分段与替换间隔继续生效；少量长消息未达到事件门槛，或近期材料仍在保留窗口内时，会按原规则等待。

### 压缩后的任务与用户原话

todo、运行状态、任务提醒和技能目录不参与事实摘要。直接调用和能够确认只调用任务／回查工具并输出其结果的 PTC 程序使用同一筛选；混合真实工作或无法确定用途的程序保留，不凭一次 Todo 调用排除整段脚本。todo 快照不形成分段边界。成功应用压缩后清理旧快照，从任务账本取最新版，放到前置 CoT 后；无 CoT 时放到系统前缀后。平时依然仅在任务变化时追加新版，下一次压缩统一清旧。用户原话属于详细资料中的逐字文本附件；仅摘要模式不携带全文，但可用 recall 回查。

任务重新注入与压缩使用同一可恢复事务，并计入替换收益；不会因为生成失败先删任务。此位置会随压缩一起变化，不保证前缀缓存零影响。

开发分支：fork 会保存截止位置已经继承的摘要及关联资料，可继续按原摘要编号回查详细文档和附件，重启后保留。资料快照只供该分支读取，父会话随后产生的资料不会加入；私有会话的分支继续使用会话隔离，不随全局默认范围的修改扩大。

## 冷只读与范围边界

打开尚未激活会话的上下文／范围时，使用匹配宿主 session controller 的公共只读 inspection，不为查询激活 Agent、创建 OMD 状态账本或触发整理请求。读取失败保留原日志、错误与重试入口；保存范围前再次检查会话是否已经开始，不能以过时读取修改已锁定范围。fork 保留继承截点，私有分支不因全局默认变化扩大共享。无项目 Chat 的文件目录不作为 Dream 项目，后代、旧作业及历史目录变更继续隔离，详见[Dream](dream-memory.md)。

工具、证据执行、CodeGraph 与 Workflow 跟随宿主当前执行目录；项目身份和上下文／Dream 归属仍按原生绑定处理，目录切换不扩大文件权限或共享范围。

## 核心上下文优化

默认开启的一体化工具精简、原文回查、AST 搜索与按需目录，见[上下文优化](context-optimization.md)。设置开关与下方历史压缩分别保存。

## 上下文占用读数

控制台的圆环显示宿主计量的当前总占用与模型窗口比例；色条单独显示内容构成，区分系统提示、目录／技能指令、OMD 摘要与注入、用户、模型、工具结果、其他上下文及当前请求头的工具定义。分类与工具定义使用本地估算，不作为渠道精确账单。未知来源归入其他上下文，不归入系统提示或工具结果。

“计量差额”是当前总占用减去内容及工具定义估算的有符号差值，单列显示、不计入色条，也不冒充工具定义。工具定义或消息节点不可读时不计算完整内容合计与差额；输入、输出、缓存回执与本地估算使用同一计量契约。替换、回退、换路由或图片卸载后，旧回执的前缀基准失效；替换后预览重新估算新上下文，不继续减用旧差额。

## Auto Compact 自动压缩

在 OMD 控制台的上下文设置中启用 **Auto Compact**，设置触发 Token 阈值与压缩方式。默认关闭，阈值预填 **400,000 tokens**；实际触发上限同时受当前模型窗口、输出预留和安全余量约束。

- **摘要＋资料**：保留摘要及详细资料，降低长历史占用。
- **仅摘要**：更紧凑；详细资料退出当前上下文，但仍保留原文与附件回查入口。

自动压缩与正在进行的维护事务互斥，使用已准备内容并按需要整理剩余材料；失败保留错误，不删除原始记录。启用记忆缓存模式后，优先复用能容纳完整任务的成功主请求；没有可用快照时使用分段请求。后台整理会产生模型用量。主会话与子代理有各自执行边界，不把一次压缩等同于无限上下文。

## 手动压缩

右侧工作台 → **上下文 → 手动压缩** 提供与输入框一致的操作：

| 命令 | 范围 | 是否调用模型 |
| --- | --- | --- |
| `/compact` | 应用已准备的中枢方案；明确选段时按用户选择的详细或简要模式应用 | 否 |
| `/compact-p` | 全部已准备片段（包括尚为原文或已经详细替换的片段）切换为仅摘要；未处理原文不变 | 否 |
| `/compact-f` | 将当前完整对话、用户消息、工具结果、旧摘要和历史思考重新汇总为一份摘要；保留前置 Trace，不保留近期原文窗口 | 是，使用中枢的后台模型配置 |

前置 CoT 的保存位置失效时，先按原始用户消息内容核对当前上下文中的唯一 Trace 承载消息，再恢复位置；不会把普通消息或日志事件当作前置 CoT，也不清空会话或摘要来解除阻塞。停止后的手动压缩仍受宿主维护互斥和取消信号约束。

全量压缩确认只用于当前会话，切换会话后须重新确认。已提交的操作仍作用于原会话，其迟到回执不会清除新会话的选择或显示为新会话完成；选段操作失败保留勾选供重试。全量模式保留系统提示词、前置 CoT、当前工具定义和用户手写全局背景，不删除原始日志或详细资料存档。图片与文件保存原始引用并可回查，不凭空生成视觉描述。全量模式可能损失细节；失败或摘要未缩短时不替换原文，写入中断使用现有事务恢复。

执行中的会话会将命令排队，在下一次请求边界执行；侧栏显示排队、生成中、失败和完成状态。手动压缩会取消本会话未完成的预处理、中枢或主动整理请求，防止旧结果覆盖手动选择。已归档的用户原文和详细资料不会在简要模式下重新灌入；保留的前置 Trace 仍位于摘要之前。

## 搜索原始对话

明确搜索当前会话原文时使用 `recall({search: 'original', query: '关键词'})`。结果来自原始会话事件，按有界分页返回匹配原文及来源位置；需要更多结果时按返回的分页信息继续读取。搜索后仍可按事件区间回查上下文，图片和附件按原始引用读取。

跨会话搜索须显式指定 `sessionId`，例如 `recall({search: 'original', query: '关键词', sessionId: '目标会话编号'})`。省略 `sessionId` 只搜索当前会话，不自动扩大范围。原有 `recall({query: '关键词'})` 继续过滤摘要目录，不自动切换为原文搜索。

升级前备份原 DSH 数据目录。上下文后台调用仍会产生用量，摘要不保证无损；请保留原始事件与必要的外部验证。
