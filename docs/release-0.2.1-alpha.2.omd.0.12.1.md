# OMD 0.2.1-alpha.2.omd.0.12.1（候选，未正式发布）

配对官方 DSH **0.2.1-alpha.2**，内置 **OpenCU 1.4.1**。官方来源为标签 `dsh-v0.2.1-alpha.2`、提交 `d743267388641bc76f17c45ce8b4c231aed1d32c`。rc.2 与 alpha.1 的 0.12.1 独立构建各自保留原 SDK、组件快照与锁文件；alpha.2 包不能装入旧宿主。

当前公开安装仍为对应宿主的 **0.10.0**。本候选没有公开 tag 或下载资产；按[本地候选验收](upgrade.md#candidate-install)使用实际交付并核验过的包。Intelligent UI 继续为独立可选插件，默认不安装。

- 工作流复用 alpha.2 的公开原生 activation API，由宿主负责子会话创建、输入、结果、取消、后代清理及释放，移除已退役的 in-process driver。自定义预设在首个输入前生效，保留工作树、原项目身份、共享预算、运行记录及冷恢复。
- 执行目录跟随原生 `working_directory`；读取、命令、CodeGraph 与工作流使用当前目录，项目身份与权限根目录继续保持原约束。alpha.2 的 PTC 仅展示原生 `run_code`，工具能力通过公开 SDK 调用；旧宿主保留其原生展示能力。
- 不可信的工作流结果或清理失败如实记录为失败，阻止错误结果进入已完成缓存；无法确认清理完成时保留工作树和恢复材料。
- OpenCU 在控制连接停止后继续保存受控浏览器的下载，验证实际文件后交付为持久附件。普通工具与 PTC 均保留预览、失败原因和冷启动后的文件访问。
- Pro 优先使用模型已声明的 `xhigh`；未提供该档时使用模型最高档。Ultracode 保留最高档排序，普通模式保留用户选择。
- OMAA 配套候选为对应宿主的 `omaa.0.14.2`：原生子会话和当前执行目录适配、只读检查点边界、ZCode 不同执行目录的缓存隔离，保留五产品模式、原始项目边界及恢复能力。其他插件须使用对应 SDK 的候选包，不能通过放宽 peer 或兼容检查混装。

Mac 隔离 Web 的本候选完整八场景会话基线、真实 Web 明暗操作、工作流原生生命周期及 Pro 普通／PTC 请求已有实际验证。rc.2 与 alpha.1 的独立构建各自完成八场景基线及原生安装、启停、恢复和卸载。五插件完整组合的界面交互、两种加载顺序与 a1→a2 同目录升级验收正在收尾，尚不据此宣称全部推荐生态通过。结果分别绑定实际包、SDK、来源和清理证据；历史 CI 不归给本候选。
