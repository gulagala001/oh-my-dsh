# Workflow 执行与恢复

[文档目录](README.md) · [后台任务](runtime-state-background.md)

本页介绍 Ultra 的 Workflow、Agent Team、自由三种子模式，以及 Workflow 的执行与恢复：从任务拆解、子代理委派，到工作流组合与结果收拢。版本与安装条件见[安装指南](install.md)。

Workflow 复用 DSH 原生子代理、工具循环、会话和 Jobs。可以让代理用脚本组织读取、实现、验证等阶段，子代理能够直接修改代码。普通模式下需要用户授权工作流或多代理协作。

会话标题旁的子代理入口显示任务名称，并提供 Workflow 当前阶段入口；展开可查看原生工作流面板中的阶段分组、成员和执行状态。对话中的工作流记录仍保留。`agent()` 的 `label` 同时用于进度与 DSH 子代理名称；省略时使用任务摘要，右侧子会话标签会随名称加载更新。

当前匹配构建使用原生 subagent activation 的准入、创建、输入、结果、取消、后代排空与释放生命周期，不加载退役 in-process driver。结果读取、结构校验或清理失败不能写成成功缓存，取消／清理状态仍由真实宿主处理。路径使用宿主当前执行目录，项目身份、权限与记忆隔离保留；不只搬单个工作流文件或改版本号混用宿主。

## 独立插件与 OMD 入口

工作流运行时、工具、阶段／成员面板与输出预算由 **DSH Workflow（dsh-workflow-plus）** 提供，已有[独立 rc.2 发行](https://github.com/gulagala001/dsh-workflow/releases/tag/v0.1.1-dsh.0.2.1-rc.2)。OMD 继续将它组合进 Ultra 与工具入口；工作流的保存、嵌套、worktree、后台与续跑语义保留。匹配的独立／内置入口共用实际宿主作用域中的运行时；原生 Session、Jobs 和权限仍由 DSH 管理。[插件架构](architecture.md)

## Ultra 与模型面板

输入框的模型入口提供模型搜索、推理滑杆和恢复默认。原生推理档之后是 Ultra；开启后可选择 Workflow、Agent Team、自由，默认自由。三种子模式统一优先使用模型声明支持的 `xhigh`，未声明该档时使用最高支持档；普通模式保留用户原生档位。模式和子模式保存在插件的会话存档，实际推理参数保存在原生模型选择日志；回到原生档或恢复默认会关闭 Ultra，并记住所选子模式。切换模型会保留模式和子模式，并按同一规则选择推理档位；未声明推理档位的模型沿用提供方默认设置。保存失败保留原状态并显示可访问提示。

三种子模式共用同一段[质量与主动性要求](../src/cc-adaptation/prompts/runtime/ultra-quality.md)：优先追求充分、正确且有依据的完整结果，不为省 token 或尽早结束而削减必要工作；及时委派、主动处理难点并完善实际交付，不固定人数、阶段或审查轮数。用户明确的范围与预算仍然有效。

- **Workflow**：通过工作流委派具体要求，按实际依赖组合调用和并行分支；编写参考提供工具 API 与可选模式，不规定阶段顺序。基础完成纪律、运行反馈、用户明确要求的检查及 BT 设置仍各自生效。
- **Agent Team**：实质任务默认主动委派；在 DSH 已开启 Agent Team 时，使用原生团队成员、通信与任务板组织协作。发现可独立推进的工作就及时派发或复用成员，主代理同时推进其余工作，不固定人数或流程。开关与团队界面均由 DSH 负责，OMD 不自动开启 Team。
- **自由**：实质任务默认主动委派，按任务需要选择普通子代理、已可用的原生团队或工作流。自由指协作方式自由，不代表省略协作；不固定人数、角色或阶段。闲聊、简单问答和琐碎机械操作可直接完成，实际工具与界面由 DSH 提供。

DSH 未开启 Agent Team 时，中间的 Agent Team 选项隐藏。原先记住的 Agent Team 选择会暂用自由，保留原记忆；重新可用后仍可恢复。OMD 不新增团队开关、工具别名或团队面板。

仅 Workflow 加载工作流编写参考；Agent Team 和自由不因启用 Ultra 被强制使用 Workflow。提示词、工具与执行机制共同工作，模型是否遵循策略仍取决于其能力。模式不会改变宿主权限。

当前子模式策略以完整系统提示段装配，每轮固定使用该轮开始时捕获的模式。切换模式或子模式会更新对应提示；运行中的变更在下一轮生效。关闭模式时移除模式提示并恢复普通授权规则，所选子模式仍保存。旧 Pro 状态只读迁移为 Ultra / Workflow；旧 Ultracode 状态按关闭处理，不自动启用新模式。普通文字中的 `pro`、`ultracode` 不触发工作模式。在宿主允许的 preset 切换中，切到原版 preset 时暂停模式，回到 OMD preset 时恢复已保存状态；已开始的会话仍遵守宿主的 preset 锁定规则。

Workflow 策略沿用原 Pro 的工作流参考；Agent Team 和自由使用各自的模式提示。DSH 采用完整系统提示词段装配，以便关闭或停用插件时清除旧指令。DSH 当前没有 `/clear` 命令；上下文压缩使用既有 `/compact-p`、`/compact-f`，不会改变已保存模式。

匹配 Subscriptions 的 ChatGPT 订阅渠道支持 Fast 的模型显示闪电，兼容 `codex` 与 `openai-codex` 别名；缺少实际能力时隐藏。账号授权、付费和服务端优先级由提供方管理，状态持久化和账号路由由实际 Subscriptions 版本负责。

停用插件后，普通 DSH 会话继续可用，原生读取器仍可读取已有 OMD 历史；OMD preset 自身已卸载，因此该 preset 的会话需重新启用插件后才能继续，已保存模式届时恢复。

界面保留蓝色填充、粒子、拖动时滑块放大和档位过渡；Ultra 沿用原 Pro 的渐变、粒子与光晕，遵循系统减少动态效果设置。模型变更遵循宿主规则；模式和子模式在每轮开始时固定，运行中的变更在下一轮生效。

## 脚本与输入

模型调用 `workflow` 时，在 `script` 中直接传入 JavaScript；无需先写文件：

```js
export const meta = {
  name: 'review-modules',
  description: '按模块查找并验证问题',
  phases: [{ title: 'Review' }],
};
phase('Review');
return await pipeline(args, name => agent(`检查模块 ${name}`, { label: name }));
```

`args` 可直接传数组或对象，例如 `['auth', 'storage']`。元数据必须是纯字面量；也兼容单独的 `meta` 参数。脚本支持顶层 `await`，以 `return` 返回 JSON 值。代理默认继承主会话的模型；需要时可独立指定 `provider`、`model`、`effort`。

`pipeline` 让每项工作独立经过后续阶段；`parallel` 等待全部分支汇合。子代理失败仍返回 `null`，但独立保存失败记录：前台回执通过 `failures` 给出失败调用序号、子会话（已创建时）、原因及原始错误分类；即使脚本过滤了 `null`，这些记录仍会返回。外层脚本执行结束不表示全部子任务成功，界面会显示失败状态。参数错误和运行上限会使脚本失败。结构化结果沿用宿主支持的 object-root JSON Schema 子集。

## 隔离与代理类型

`agent(prompt, {isolation: 'worktree'})` 在当前仓库 HEAD 创建独立工作区，位置为工作区内的 `.omd/worktrees/`。父目录的未提交改动不会复制过去。代理停止后，无变化的目录自动移除；文件改动、未跟踪文件、忽略文件或新提交都会保留，返回 `worktrees` 中的路径供检查和合并。不会自动合并或覆盖父工作区。

隔离工作区继承发起项目的上下文范围；选择私有会话范围时，仍归属原来的私有会话，不扩大为项目共享。

隔离要求本地 Git 仓库与可写权限；原有沙箱限制继续生效。无法确认目录干净时保留目录并报告原因。

`agentType` 使用 DSH 已注册的 agent preset id；`general-purpose` 继承当前 preset。例如 `omd-ptc` 使用 PTC 工具界面。未注册或无法启动的 preset 会明确报错。

## 保存、嵌套与续跑

每次调用返回 `runId`、`scriptPath` 和 `transcriptDir`。可编辑返回的脚本，再以 `scriptPath` 调用。放在工作区 `.omd/workflows/<name>.js` 的脚本可通过 `name` 调用。三种入口 `script`、`scriptPath`、`name` 每次只选一种。

脚本内的 `workflow('name', args)` 或 `workflow({scriptPath}, args)` 支持一层嵌套，共享并发数、总代理数、取消信号与预算。`Date.now()`、`Math.random()` 和无参数 `new Date()` 不可用；需要时间或随机输入时通过 `args` 显式传入。

取消、失败或编辑脚本后，可带 `resumeFromRunId` 重放同一会话内的运行。按调用开始顺序复用最长的、未变化且成功完成的前缀；第一处变化、新调用、失败或未完成调用及后续部分重新执行。结果为空字符串也可能是有效缓存，可查看 `transcriptDir` 下的 `journal.jsonl` 核对。

恢复前应检查失败原因、已有产物与操作副作用；后续调用中可能包含已成功执行的工作，不能将续跑等同于只补跑失败项。用户取消不会自动重启，额度耗尽与网络错误保留各自原因；本功能不新增无限重试或长期断网自动续跑。缺少有效结构化结果的调用不作为成功缓存。

仍在运行或正在被另一轮恢复的源运行不能并发重放。取消会等待已经开始的子代理启动和清理；清理无法完成时保持恢复锁，直到进程退出。进程崩溃后可以从已持久保存的成功前缀恢复，不把未完成调用当作成功。

## 输出 token 目标

在人类消息末尾添加 `+500k`，可将本回合的共享输出目标设为 500,000 token。脚本通过 `budget.total`、`budget.spent()`、`budget.remaining()` 读取。未设置时没有目标上限；仍有防止失控的原生并发与总调用数限制。

达到目标后停止启动新的代理，正在运行的调用可以继续结束，因此最终数值可能超过目标。主会话与代理的输出一并计入，不重复计算推理 token；已完成缓存不产生新的模型调用。用量缺失时明确标记，已设置目标的运行停止继续派发。后台工作保留发起时的预算，新一轮用户输入不会重置旧后台工作的计数。

这个输出目标与 `/预算` 的会话用量提示分别保存；后者仍按原有规则统计输入、缓存、输出、轮次和时间。

开发分支：普通 fork 独立设置输出目标并统计用量，不消耗父会话的预算；fork 发起的真正子代理共享该 fork 的预算。修复也会停止沿用旧版误挂接到父会话的预算归属。

## 后台运行

OMD-PTC 的普通业务仍走 `run_code`，只有实际作用域和 registry 身份经匹配 alpha.2 适配核对后，保留四个直调后台控制：`job_output`、`job_list`、`job_kill`、`runtime_status`。不替换原生 Tools、不绕过权限／取消或嵌套 SDK；这是目标宿主的受控展示适配，不是跨版本公共契约。

`run_in_background: true` 返回原生 job id 和已保存的脚本路径。用 `job_output` 读取结果，`job_kill` 请求取消；完成通知沿用 DSH Jobs。子任务失败时，后台 job 标为失败，仍保留已经返回的结果、失败明细、运行 ID、脚本及 journal 路径。取消等待会明确返回取消原因，取消等待本身不重复启动任务。运行完成、结果已读取和验证通过是不同状态。

执行证据从 BT 菜单 **查看任务证据** 打开；右侧栏 **OMD 控制台** 的 **调用日志** 看真实调用、用量、耗时，**上下文** 与 **记忆** 分别看整理及来源；文件、终端和第三方内容入口保留。
