# OMD 与其他插件共用

[English](plugin-compatibility_EN.md) · [文档目录](README.md) · [安装与配对](install.md)

OMD 保留 DSH 原生工具、技能、会话及第三方插件入口。**请使用与完整宿主版本匹配的插件。**

## 选择匹配工件

当前发行匹配 DSH `0.2.1-rc.5`：OMD `1.0.2`、内置／独立 OpenCU `2.2.1`。DSH rc.1／rc.2 使用各自历史固定构建。IUI、OMAA 等独立项目也需各自对应宿主的构建，不把相同前端只换元数据当作适配。

不要用旧包、旧 HEAD 或版本豁免覆盖当前成果；备份实际数据，保留显式设置、账号及第三方来源。

## 原生工具与所有权

- 原生 registry、SDK、lookup、调度、权限、取消和插件作用域由宿主管理。
- OMD 只在自己的 preset 作用域提供 PTC 展示；普通业务走 `run_code`，匹配作用域保留四个后台直调控制。
- `standard` 可见的工具不保证对所有 preset 可见，应检查实际作用域。
- 请求投影可逆；卸载只撤回自有贡献，保留第三方后加包装、注册及公共插槽。
- Loader 移除条目保留用户原配置，不把 bundle effective patch 整套写入用户配置。

## 新版 OpenCU 已默认内置

安装新版 OMD 不用再装一份 OpenCU。独立安装保留，共装共享同一核心、工具及自动呈现入口。旧 1.3.0 过渡快照已被新版替换。

完整内置浏览器、批注和原生监看需要匹配的 Host／Client／preload；插件本身不会自动修改 stock DSH。普通文字与文件使用不需要先准备电脑控制。[使用与边界](computer-use.md)

## 独立产品与组合使用

Workflow、Rewind、DeepSeek Workbench、Persona 和 Extensions 均有独立正式发行；Glyph 随主题插件提供。OpenCU 继续支持独立使用，主题管理也有专门产品。完整职责、固定发行和共装行为见[插件架构](architecture.md)。独立产品各自完整，不以 OMD 的版本号代替它们的宿主要求。

## 其他插件与协作边界

| 项目 | 边界 |
| --- | --- |
| **Intelligent UI** | 独立交互内容能力；OMD 维护推荐入口、完整版本匹配、公共插槽和工具投影，不接管其实现与数据。 |
| **OMAA** | 独立 preset 和功能，可通过支持的 workflow／模式入口配合使用。 |
| **Subscriptions** | 独立登录、账号池、路由与 Fast 持久化；OMD 不提供账号、额度或服务端优先级保证。 |
| **Intent／需求理解** | 独立、默认关闭，与 OMD 系统提示词增强和手动草稿优化分开。 |
| **[dsh-ops](dsh-ops.md)** | T-Auto 开发的文件、文档与命令工具，支持按需工具发现和结果引用。提供固定上游 `0.4.1` 的 rc.3 兼容包；普通模式与 PTC 均保留宿主权限、沙箱及原生工具。 |
| **DeepSeek Workbench** | 提供网页聊天与迁移的独立产品；OMD 内置入口在“功能”区控制，另装的独立包由 DSH 插件页管理。 |
| **OpenDesign、标准插件** | 保留各自技能、工具、UI 所有权、账号要求和许可。 |
| **开发注入项目** | 无标准工件时按独立项目说明，不伪装成可直接安装的包。 |

## 推荐、更新与数据

插件安装预检接在运行中宿主的 `pluginManager`，不依赖市场名称或修改市场界面。`installBundle`、`setBundleEnabled` 和可定位到 bundle 的 `setPluginEnabled` 使用同一预检；OMD 推荐更新会先检查候选，再执行旧包移除。预检使用当前已选 bundle 的代码和启停状态，不复制第三方私有配置或账号，因此需要外部服务的插件可能只能给出“未完成”。首次启动检查按实际显示的引导继续，也接受没有账号引导的正常主界面；无需填写 API Key。候选入口必须出现在原生清单并完成加载，白屏、脚本失败和运行错误仍会拦截；等待超时标为“预检未完成”。它检查基础运行，不承诺所有业务功能或延迟触发问题。

macOS／Linux 的控制器与隔离宿主在同一个临时进程内复用模块，浏览器继续独立运行，完整保留宿主启动、插件启用、页面、输入入口和设置检查；Windows 保留原先的独立宿主进程。包准备复用已有原生工具缓存（包括 Corepack 的默认缓存），试运行环境仍独立。全部检查与进程清理完成才算通过；提前退出、异常退出或清理超时均不会放行。

当前验证以 DSH `0.2.1-rc.5` 的 macOS 隔离宿主为准，已检查真实安装流程、dsh-market 桌面桥接及桌面应用自带 CLI 的隔离启动；未更新运行中的桌面应用。macOS／Linux 检查期间采样进程树与临时目录，达到约 2 GiB 进程内存合计或 1 GiB 临时文件时停止检查；采样预算不是操作系统硬配额。Windows 使用进程树终止和超时控制，尚未做真机验收，也没有宣称同等 RSS／磁盘采样保护。其他宿主构建及外部命令行的全覆盖仍需独立接入与验证。预检不会安装常驻守护进程或改写用户的命令行入口。

推荐目录列用途、原作者、固定来源、完整宿主、SHA-256 与状态。未知宿主、缺失工件及未发布目标不提供虚假可安装入口。由当前 profile 原生管理器安装；桌面使用应用或自带 CLI。

当前第三方固定目录：BC 0.1.202、dsh-ops 0.1.0（rc.3 构建）、订阅登录 0.9.11、OpenDesign 0.1.0-omd.1.0.0、需求理解 0.3.3（rc.3 构建）、插件市场 1.70.3、无限四代 0.4.0 固定源码、动态思考文案 0.38.0、DSH × Blender 2.6.1、小鲸鱼记账挂件 0.4.2。目录记录各自来源与 SHA-256；真实账号、Blender 端连接与付费请求仍按各插件要求配置。

已有较旧或不兼容的安装会显示可用的“更新”入口；错误提示不会遮住更新操作。需求理解配置使用原生 profile，保留审查／自动模式、只读查证与草稿保护。[本版说明](release-1.0.1.md)

自动更新默认关闭，仅处理已安装、启用且符合目录的发行条目；不跨宿主、不自动批准脚本、不重启。账号、OAuth、Fast 与付费效果需分别确认。

dsh-ops 的第三方功能页提供安装／启用开关，按完整宿主版本与运行平台选择固定兼容包；关闭保留插件数据。目录更新只使用已登记的兼容发行，不跟随上游 `latest`。外部插件市场或 CLI 升级可以绕过目录的版本固定，升级后应重新核对匹配版本。[安装与使用](dsh-ops.md)

停用／卸载保留会话、草稿、附件、设置、短记忆和独立插件数据；缺 preset 的旧会话可能需要恢复原插件。

反馈提供完整三方版本、加载顺序、profile、最短复现和第一处脱敏错误。不要清数据或禁用全部增强来掩盖冲突。[排障](troubleshooting.md) · [来源与许可](../THIRD_PARTY_NOTICES.md)
