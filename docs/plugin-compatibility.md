# OMD 与其他插件共用

[English](plugin-compatibility_EN.md) · [文档目录](README.md) · [安装与配对](install.md)

OMD 保留 DSH 原生工具、技能、会话及第三方插件入口。**请使用与完整宿主版本匹配的插件。**

## 选择匹配工件

当前源码默认匹配 DSH `0.2.1-rc.2`：OMD `0.19.0`、内置／独立 OpenCU `2.0.6`。DSH `0.2.1-rc.1` 使用独立构建；这两个完整宿主版本是当前支持范围。IUI、OMAA 等独立项目也需各自对应宿主的构建，不把相同前端只换元数据当作适配。

不要用旧包、旧 HEAD 或版本豁免覆盖当前成果；备份实际数据，保留显式设置、账号及第三方来源。

## 原生工具与所有权

- 原生 registry、SDK、lookup、调度、权限、取消和插件作用域由宿主管理。
- OMD 只在自己的 preset 作用域提供 PTC 展示；普通业务走 `run_code`，匹配作用域保留四个后台直调控制。
- `standard` 可见的工具不保证对所有 preset 可见，应检查实际作用域。
- 请求投影可逆；卸载只撤回自有贡献，保留第三方后加包装、注册及公共插槽。
- Loader 移除条目保留用户原配置，不把 bundle effective patch 整套写入用户配置。

## 新版 OpenCU 已默认内置

安装新版 OMD 不用再装一份 OpenCU。独立安装保留，共装共享同一核心、工具及自动呈现入口。旧 1.3.0 过渡快照已被新版替换。

完整内置浏览器、批注和原生监看需要匹配的 Host／Client／preload；插件本身不会自动修改 stock DSH。普通文字与文件使用不需要先准备电脑控制。[使用与边界](computer-use.md)

## 独立配套项目

| 项目 | 边界 |
| --- | --- |
| **Intelligent UI** | 独立交互内容能力；OMD 维护推荐入口、完整版本匹配、公共插槽和工具投影，不接管其实现与数据。 |
| **OMAA** | 独立 preset 和功能，可通过支持的 workflow／模式入口配合使用。 |
| **Subscriptions** | 独立登录、账号池、路由与 Fast 持久化；OMD 不提供账号、额度或服务端优先级保证。 |
| **Intent／需求理解** | 独立、默认关闭，与 OMD 系统提示词增强和手动草稿优化分开。 |
| **[dsh-ops](dsh-ops.md)** | T-Auto 开发的文件、文档与命令工具，支持按需工具发现和结果引用。提供固定上游 `0.4.1` 的 rc.1／rc.2 兼容包；普通模式与 PTC 均保留宿主权限、沙箱及原生工具。 |
| **DeepSeek Workbench** | OMD 内置；推荐页提供入口与状态，不作为第三方包安装、更新或卸载。 |
| **OpenDesign、标准插件** | 保留各自技能、工具、UI 所有权、账号要求和许可。 |
| **开发注入项目** | 无标准工件时按独立项目说明，不伪装成可直接安装的包。 |

## 推荐、更新与数据

推荐目录列用途、原作者、固定来源、完整宿主、SHA-256 与状态。未知宿主、缺失工件及未发布目标不提供虚假可安装入口。由当前 profile 原生管理器安装；桌面使用应用或自带 CLI。

自动更新默认关闭，仅处理已安装、启用且符合目录的发行条目；不跨宿主、不自动批准脚本、不重启。账号、OAuth、Fast 与付费效果需分别确认。

dsh-ops 的第三方功能页提供安装／启用开关，按完整宿主版本与运行平台选择固定兼容包；关闭保留插件数据。目录更新只使用已登记的兼容发行，不跟随上游 `latest`。外部插件市场或 CLI 升级可以绕过目录的版本固定，升级后应重新核对匹配版本。[安装与使用](dsh-ops.md)

停用／卸载保留会话、草稿、附件、设置、短记忆和独立插件数据；缺 preset 的旧会话可能需要恢复原插件。

反馈提供完整三方版本、加载顺序、profile、最短复现和第一处脱敏错误。不要清数据或禁用全部增强来掩盖冲突。[排障](troubleshooting.md) · [来源与许可](../THIRD_PARTY_NOTICES.md)
