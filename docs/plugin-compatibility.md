# 和其他插件一起用

[English](plugin-compatibility_EN.md) · [文档目录](README.md) · [安装](install.md) · [插件结构](architecture.md)

OMD 保留 DSH 原生的工具、技能、会话和第三方插件入口。**请用和你的 DSH 完整版本匹配的插件。**

## 版本要对上

当前 OMD 1.3.18 对应 DSH 0.2.2-rc.2，内置 OpenCU 2.2.12。旧版 DSH 用各自的旧版安装包。IUI、OMAA 等独立项目也要用对应 DSH 版本的构建。

不要用旧包或关掉版本检查来覆盖现有安装；先备份数据，保留你的设置、账号和第三方来源。

## 工具归谁管

- 工具注册、SDK、调度、权限、取消和插件作用域都由 DSH 管理。
- OMD 只在自己的预设里提供 PTC：业务工具走 `run_code`，四个后台任务工具保持直接调用。
- 在 `standard` 里能看到的工具，不一定在每个预设里都能看到，以实际作用域为准。
- 卸载 OMD 只撤回它自己加的东西，第三方后来加的包装、注册和公共插槽都保留，你原来的配置也不会被整体改写。

见[提示词来源](prompt-adaptation.md)。

<a id="opencu"></a>

## OpenCU 已经内置

装了 OMD 就不用再装 OpenCU。也可以单独装 OpenCU，两者共装时用同一套核心和工具。

内嵌浏览器、批注和原生监看需要配套的 DSH 桌面版；只装插件不会改动原版 DSH。普通的文字和文件任务不需要先准备电脑操作。见[电脑与浏览器](computer-use.md)。

## 独立插件

Workflow、Rewind、DeepSeek Workbench、Persona、Extensions、OpenCU 和主题管理都有独立版，Glyph 随主题插件提供。每个独立版有自己的 DSH 版本要求。见[插件结构](architecture.md)。

| 插件 | 和 OMD 的关系 |
| --- | --- |
| **Intelligent UI** | 独立的交互内容插件。OMD 提供推荐入口、版本匹配、公共插槽和工具接入，不管它的实现和数据 |
| **OMAA** | 独立的智能体预设，可以通过 workflow 或模式入口配合使用 |
| **Subscription Login** | 独立负责登录、账号池、路由和 Fast。OMD 不提供账号、额度或优先级 |
| **需求理解** | 独立插件，默认关，和 OMD 的提示词增强、✨ 优化是两回事 |
| **[dsh-ops](dsh-ops.md)** | T-Auto 开发的文件、文档和命令工具，基于上游 0.4.1；普通模式和 PTC 都保留 DSH 的权限、沙箱和原生工具 |
| **DeepSeek Workbench** | OMD 内置的在"功能"里开关，另装的独立版在 DSH 插件页管理 |
| **OpenDesign 等标准插件** | 各自的技能、工具、界面、账号要求和许可都不变 |

## 第三方目录

**设置 → Oh My DSH → 第三方** 列出每个插件的用途、原作者、固定来源、适配的 DSH 版本、SHA-256 和状态。DSH 版本不匹配、缺安装包或还没发布的，不显示安装按钮。安装用当前 profile 的插件管理；桌面版用应用或自带的命令行。

当前目录：Billion Context 0.1.202、dsh-ops 0.1.0、订阅登录 0.9.12、OpenDesign 0.1.0-omd.1.0.0、需求理解 0.3.4、插件市场 1.70.3、无限四代 0.4.0、动态思考文案 0.38.0、DSH × Blender 2.6.1、小鲸鱼记账挂件 0.4.2。账号、Blender 连接和付费请求按各插件的要求配置。

- 已装的旧版或不兼容版本会显示 **更新** 按钮。
- 自动更新默认关，只处理已安装、已启用且在目录里的条目，不跨 DSH 版本、不自动批准脚本、不重启。
- dsh-ops 只装登记过的兼容版，不跟上游的 latest。从别的市场或命令行装了其他版本时，请自己核对。

## 插件安装预检

通过 DSH 插件页、工具调用或桌面版 dsh-market 安装、更新或启用插件时，OMD 先在临时 DSH 里试一次：插件要出现在插件列表里并加载成功，白屏、脚本报错和运行错误都会被拦下。等太久会标为"预检未完成"。它检查的是能不能正常启动，不保证所有功能都没问题。

- 预检用你选中的插件代码和启停状态，不复制第三方的私有配置或账号，所以需要外部服务的插件可能只能显示"未完成"。不需要填 API Key。
- 首次启动有引导时按引导继续，没有引导、直接进主界面也算正常。
- macOS／Linux 上，检查期间进程内存合计约 2 GiB 或临时文件约 1 GiB 时停止检查。Windows 用进程树终止和超时控制。
- 全部检查和进程清理完成才算通过。提前退出、异常退出或清理超时都不放行。
- 预检不装常驻进程，也不改你的命令行入口。
- 通过 npm 来源更新时，预检在整个更新前跑一次；取消预检不会先删掉旧版，更新失败恢复旧版时也不会再预检一次。

从命令行、npm／pnpm 或手动改目录装的插件不经过预检。

## 停用和卸载

停用或卸载 OMD 会保留会话、草稿、附件、设置、短记忆和独立插件的数据。用 OMD 预设建的旧会话，在 OMD 不在时可能要先装回来才能打开。

反馈冲突时，写清楚涉及的各插件完整版本、加载顺序、profile、最短复现步骤和第一条报错（去掉隐私）。不要用清数据或关掉所有增强来掩盖冲突。见[排障](troubleshooting.md)和[第三方声明](../THIRD_PARTY_NOTICES.md)。
